## Known Gotchas

- **Prototype lives under `prototype/`**: All demo source is at `prototype/src/`, `prototype/public/`, etc. The root `public/` doesn't exist — don't look for files at the repo root level.
- **Two separate demos exist**: (1) Original simulated browser demo at `prototype/public/index.html` with scenes managed by `app.js`, and (2) Multi-site redirect demo at `prototype/public/demo/spacebook/` with real Express routes in `src/routes/demo.ts`. Both need updating when branding changes.
- **`dist/` is untracked**: The `prototype/dist/` directory contains compiled JS output from `tsc`. It's not committed but is generated by `npm run build`.
- **`node_modules/` is untracked**: The whole prototype directory including deps is not yet committed.
- **Original demo CSS classes kept**: `.scene--barfinder`, `.barfinder-logo`, `.barfinder-tagline` in the original demo are internal class names that still say "barfinder" even though displayed text says "Spacebook". This is intentional — see Architecture Decisions.

## Established Patterns

- **Demo route flow**: Spacebook `start-verify` → Issuer login page (server-rendered) → authenticate → issue SD-JWT → redirect back to callback → verify → store in localStorage → show access granted
- **Theme colors by site**: Spacebook uses indigo (#6366f1, #312e81, #eef2ff, #c7d2fe), Government issuer uses navy (#1e3a5f), Wallet uses blue (#2563eb)
- **Build command**: `cd prototype && npm run build` (runs `tsc`)
- **Dev server**: `cd prototype && npm run dev`
